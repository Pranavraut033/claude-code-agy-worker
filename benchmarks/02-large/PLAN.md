# Benchmark 2 plan — large package: Claude alone vs Claude + agy

Question: on a package big enough for agy's design (many files, many steps), does Claude + agy use
fewer Claude tokens than Claude alone, at equal quality? Benchmark 1 (small tasks, `RESULTS.md`)
showed agy costs +21 % Claude tokens there; this run tests the regime agy is meant for.

**Follow this plan exactly. If you must deviate, log what and why under "Deviations" in
RESULTS-large.md.** Work only under `~/agy-bench/large/`. Touch nothing in
your main project. 1 task × 2 arms = 2 runs, n = 1, no reruns.

## Budget guards (keep Claude spend bounded)
- The fixture is **generated by a script** (`gen_fixture.py`), never hand-written file by file.
- Arm A gets a hard cap: **stop at 120 tool calls** and report "capped" with what is done.
- Arm B: ≤ 2 fix-up rounds; timeout_s 3600.
- No reruns. If a run fails, record it.
- The main session does not read run diffs in full: it runs the hidden checks, reads `git diff --stat`,
  and spot-checks 3 files per arm (the same 3 for both arms: handler_03, handler_17, handler_31).

## Phase 0 — Baseline
`agy_usage()` → record Gemini 5-hour/weekly % ("before").

## Phase 1 — Fixture (generated)
Write `~/agy-bench/large/gen_fixture.py` (stdlib only, seeded `random.Random(42)`), which builds
`seed/` as a git repo:
- `app/registry.py`: old API `register(name, fn, opts)` storing into a dict; `opts` is a dict with
  keys among `timeout` (int s), `retries` (int), `tags` (list[str]).
- `app/log.py`: old logger `log(msg, level)` with level strings `"debug"|"info"|"warn"|"error"`.
- `app/handlers/handler_00.py … handler_39.py` (40 files, ~40–60 lines each). Each defines 2–3
  functions with **docstrings that state argument and return types in prose** (e.g. "items: a list of
  item dicts", "returns: the count as an int") but **no type hints**; calls `log(...)` 2–4 times with
  mixed levels; ends with 1–2 `register("name", fn, {...})` calls whose opts vary per file (some
  empty `{}`, some with `tags`, some with `retries`). Vary function shapes so a single regex can do
  the logging/registration part but **not** the type hints.
- `tests/test_handler_NN.py` for each handler (2 tests each, call the functions directly and check
  registry contents through the old API).
- `app/new_api.py` **already provided**: `@handler(name, *, timeout=30, retries=0, tags=())`
  decorator registering into the same registry, and `logger = logging.getLogger("app")`.
Commit. Expected size ≈ 40 handler files + 40 test files + 4 core files, ~3–4k lines.

## Phase 2 — The task (identical text for both arms)
"Migrate every module in `app/handlers/` to the new API in `app/new_api.py`:
1. Replace each `register("name", fn, {opts})` call with the `@handler("name", ...)` decorator on
   `fn`, mapping `timeout`/`retries`/`tags` to keyword arguments (tags as a tuple; omit defaults).
2. Replace every `log(msg, level)` call with `logger.<level>(msg)`, where `"warn"` becomes
   `warning`; import `logger` from `app.new_api`.
3. Add full type hints to every function in `app/handlers/`, derived from its docstring
   (use built-in generics: `list[dict]`, `int`, `str | None`, …).
4. Update `tests/test_handler_*.py` to check registration through the new decorator's registry
   (behaviour unchanged).
5. Delete nothing in `app/registry.py` and `app/log.py` (other code may still use them), but no file
   under `app/handlers/` may import them anymore.
Run `python3 -m unittest discover -s tests` and make sure it passes."

## Phase 3 — Hidden checks (written before any run, outside the repo: `checks/large.sh <dir>`)
PASS/FAIL per criterion:
1. All tests pass.
2. `grep -rn -E "register\\(|\\blog\\(" app/handlers/` finds nothing; no handler imports `app.registry`/`app.log`.
3. Hidden test `test_registry_hidden.py` (copied in at check time): every one of the generator's
   expected registrations exists with the exact name, timeout, retries and tags.
4. AST check (`checks/hints.py`): every function in `app/handlers/` has annotations on all params and
   the return; and the annotation matches the generator's ground-truth type map (emit the map from
   `gen_fixture.py` to `checks/types.json`). Report the match rate (e.g. 112/116).
5. `git diff --stat -- app/registry.py app/log.py app/new_api.py` is empty.

## Phase 4 — Runs (can run in parallel; separate dirs, separate agy allow-list rules not needed)
`cp -r seed runs/large-claude` and `runs/large-agy`; fresh `git init` + commit in each.
- **Arm A — Claude alone.** `general-purpose` subagent, `model: sonnet`. Task text + "Work in <dir>.
  Do it yourself, any way you like (scripts allowed); do not use agy. Hard cap: stop at 120 tool calls."
- **Arm B — Claude + agy.** `general-purpose` subagent, `model: sonnet`. Task text + "Work in <dir>.
  You are orchestrator and auditor only: read the agy skill
  (`~/.claude/plugins/cache/agy-worker/agy-worker/*/skills/agy/SKILL.md`) first, then brief agy with
  ONE package via `mcp__plugin_agy-worker_agy-worker__agy_start` (model `gemini-3.8-flash-medium`,
  allowed_files = the repo dir, run only `python3 -m unittest discover -s tests` plus read-only
  inspection, no pipes), wait with `agy_wait` or the returned wait_cmd in background, audit with
  `agy_diff` (stat + 3 files) and the tests, ≤ 2 fix-up rounds. Do not edit files yourself. Report job ids."
  Before Arm B: `agy_permissions(add=["command(python3 -m unittest discover -s tests)"])`; remove it after.

## Phase 5 — Measure
Same fields as benchmark 1 (see `RESULTS.md` § Method): Claude `subagent_tokens`, cumulative Claude
input from the transcript, Claude tool calls, wall time, agy tokens + wall (`agy_status`), fix-up rounds,
hidden checks (incl. the type-hint match rate), defects in the 3 spot-checked files, then
`agy_usage()` "after".

## Phase 6 — RESULTS-large.md
Method (≤ 8 lines), the run table, the type-hint match rate per arm, quota drop, Deviations, and a
plain conclusion comparing with benchmark 1: does the B/A Claude-token ratio drop below 1 at this
size? Caveats: n = 1, generated fixture, Sonnet orchestrator, Claude may solve parts with scripts
(that is a legitimate result). ≤ 10-line summary at the end.
